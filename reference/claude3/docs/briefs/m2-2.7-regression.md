Not tracked in git. Rules: `.claude/rules/project.md` (fixtures via `MTC_TEST_DATA_DIR`, skip when

## Inputs

- `tests/golden/cases.json` (24 + 4 fitting cases) and `tests/golden/<case>.json` written by
  the reference harness (`tests/reference_harness/main.cpp` documents every key). Per golden:
  `inputs` {pattern, source, patternRoi, matchRoi, patternSize, pickPosition, minScore,
  toleranceAngle, angleOffset, maxPosNum, maxOverlap, subPixel, usePickingBox, jawWidth,
  jawHeight, jawDistance, jawAngle, threshLower, threshUpper, greediness, minReduceLength,
  binaryThreshold, invertBinaryThreshold, stopAtLayer1, kernelSize, blurWidth, blurHeight,
  tSamples} and `matches[]` {center, cornersLT/RT/RB/LB, rectCenter, matchedAngle, pointAngle,
  score, patternIndex, hasCollision, collisionState (0 Outside, 1 Inside, 2 Collision)}.
- Fixtures under `MTC_TEST_DATA_DIR` (default `reference_source/Test Images`), paths relative
  (`Dst1.bmp`, `sample_1/pattern_1.bmp`, `fitting/template_1.bmp`). Roles: `pattern` = template,
  `source` = scene. Images are read in COLOR by the harness (cv::imread default) and converted
  to gray by the reference; do the same (`cv::imread(path)` then let the library convert).
- Golden dir: pass `MTC_GOLDEN_DIR` as a compile definition from tests/CMakeLists.txt
  (`${PROJECT_SOURCE_DIR}/tests/golden`), like `MTC_TEST_DATA_DIR`; do not use `__FILE__`.

## Mapping golden inputs to the library

- `MatchGroupConfig`: EdgeBased; `EdgeMatchConfig` {threshLower, threshUpper, kernelSize,
  minReduceLength, tSamples, maxPosNum, maxOverlap, subPixelEstimation = subPixel,
  stopAtLayer1}; `ForegroundConfig` {blurWidth, blurHeight, binaryThreshold,
  invertBinaryThreshold}. RULE (plan 6b): when `binaryThreshold >= 0` set
  `invertBinaryThreshold = true` whatever the golden says (the reference fixed-threshold branch
  always inverted). `greediness` is ignored (dropped feature).
- `MatchPatternConfig`: name "pattern", index 0, `rawImage` = pattern image (apply
  `patternRoi` when its area > 0: `img(roi).clone()`), `minScore`, `toleranceAngle`,
  `anchorPoint = pickPosition`, `angleOffset = 0`; when `usePickingBox` != 0:
  `clearanceZones = opposedBoxZones(Size2f(jawWidth, jawHeight), jawDistance, jawAngle)`.
- Conditions: `ClearanceCondition(false)` (reference semantics) when usePickingBox; nothing
  else.
- `SearchOptions`: `usingRoi` when `matchRoi` area > 0 with `roi = matchRoi` (no current
  case uses it; if one appears, golden coordinates are in the ROI crop frame, see the
  reference `cropOffsetPoint`, so subtract `region.tl()` before comparing).
- Learn through `ImageMatcher::learn()`; one matcher per case; `match(source, options,
  result)`.

## Comparison (tests/regression/golden_regression_test.cpp)

Parameterized test over every case in cases.json (`TEST_P` with the case name as the test
name suffix), `GTEST_SKIP()` when the data dir or an image is missing.

Per case:
1. `status == Ok` and `result.objects.size() >= 1` whenever the golden has matches.
2. Library object fields vs golden: `anchor` vs `center` (the golden center is the
   reference anchor), `corners()[1,2,3,0]` vs LT/RT/RB/LB, `matchedAngle` vs `matchedAngle`
   by wrapped difference, `score` vs `score`.
3. Matching: nearest neighbour, unordered: for each library object find the golden match with
   the smallest anchor distance; it must be within the tolerance; each golden match may be
   claimed once, except the duplicate rule below. Every golden match whose score is
   >= minScore + 0.01 must be claimed by some library object (matches within 0.01 of minScore
   are excluded from count comparisons, plan section 8).
4. Tolerances (same compiler as the goldens, MSVC): position <= 0.25 px, angle <= 0.1 deg,
   score <= 0.005. Expose them as constants at the top of the file and ALSO run a second,
   informational pass at the cross-compiler tolerance (1 px, 0.5 deg, 0.02) so the report
   shows which cases are tight and which are loose. If a case exceeds the tight tolerance but
   passes the loose one, mark it with `RecordProperty` and keep the assertion at the loose
   tolerance for that case ONLY if the lead agrees; first report.
5. Duplicate rule (m2-notes.md): the reference may report the same instance twice (nested
   contour regions, e.g. fitting_template4 at (829,680)); the library reports it once. A
   golden match that is within 2 px / 2 deg (wrapped) of another golden match of the same
   case with a higher score is a "golden duplicate" and is not required to be claimed.
6. State comparison when usePickingBox: library verdict vs golden `collisionState`:
   0 -> Ok, 1 -> Ng reason "inside", 2 -> Ng reason "overlap" (outcome of the condition
   named "Clearance"). Count mismatches per case and assert 0; if the rasterization differs
   at a boundary pixel (float rounding), report the case and the counts rather than loosening.
7. Print a one-line summary per case: objects / golden matches / max position error /
   max angle error / max score error / state mismatches.

Also add `tests/regression/CMakeLists.txt` with `mtc_add_test(regression ...)` (the suite
directory is already in the foreach of tests/CMakeLists.txt) and the `MTC_GOLDEN_DIR`
definition (in tests/CMakeLists.txt so every suite gets it).

## Benchmark target (tests/bench/)

`tests/bench/CMakeLists.txt` + `tests/bench/bench_main.cpp`: an executable `mtc_bench`
(not a test, not run by ctest; add `bench` to the foreach only if it has its own guard, or
add_subdirectory it directly from tests/CMakeLists.txt when `MTC_BUILD_TESTS`), that runs every
golden case N times (default 5, `--repeat`), with `--data-dir` and `--golden-dir` arguments
defaulting to the compile definitions, and prints per case: image size, pattern size, objects,
and the median of `stats.totalMs`, `foregroundMs`, `searchMs`, `conditionsMs`, `sortMs`, plus
the operator-new count of the last run (same counter technique as the unit tests, in the
bench exe only). Print a final table and the sum of medians. No assertions. Keep the
reference time for comparison out of scope (the harness prints no timings).

## Report

Per case: pass/fail at tight and loose tolerance, max errors, state mismatches, duplicates
skipped, and the bench table (Release). Any case failing the loose tolerance is a library
finding: describe the discrepancy (which objects, which fields, by how much) for the lead; do
not edit library sources or goldens.
