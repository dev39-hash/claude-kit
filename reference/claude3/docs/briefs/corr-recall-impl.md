## Implementer

1. `src/corr/corr_search.{h,cpp}`: `coarsePeakCap(const CorrLearnedPattern&, const SearchParams&,
   cv::Size srcTop)` = `max(maxPosNum, min(packingBound, kMaxCoarsePeaksPerAngle)) +
   kCandidateSlack`, `packingBound = floor(srcTopArea / ((1 - maxOverlap)^2 * tmplTopArea))`
   computed in double, clamped before any cast (maxOverlap -> 1 and tiny areas must not overflow).
   prepareSearch reserves per-angle slots, the merged list, fine slots, refined/results/deleted
   from that cap (angles * cap), and the cluster scratch.
2. Per-angle slots hold a compact peak record `{float x, y, score, angle}` (or equivalent, 16
   bytes). `match::collectPeaks` currently fills MatchParams; add a variant or adapter without
   duplicating the peak logic (shared helper in `src/match/`), keep edge mode behaviour and
   performance identical (edge goldens must stay bit-exact).
3. `coarseSearch`: after the merge and the existing deterministic sort (`match::coarseBefore`),
   `reduceClusters()` compacts the list in place: visit in sorted order, cluster centre = top
   template centre mapped back to the unrotated top-layer frame (use the existing rotation-plan
   helpers, NOT the window top-left), keep a candidate when fewer than `kClusterKeep` (12) kept
   candidates lie within `kClusterRadiusFactor * min(top template side)` (0.25). Use a uniform
   grid (cell = radius, scratch reserved once) instead of an O(n*k) scan. Then convert the kept
   records to the structure the fine stage needs.
4. Constants named in `src/match/search_common.h` or `corr_search.h` with a one-line rationale.
5. `include/mtc/correlation_match_config.h`: maxPosNum doc becomes "Minimum number of coarse
   peaks kept per rotation angle; the search keeps more when the region can hold more
