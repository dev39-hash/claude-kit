# Brief M2 2.5: ClearanceCondition (clearance zones vs foreground)

Shared spec for the tester (RED) and the implementer (GREEN). Not tracked in git.
Rules: `.claude/rules/project.md` (ALL sections; vocabulary gate: no pick/gripper/robot/
collision/workpiece/jaw words in include/ src/ or test names; ASCII only; Angle convention:
positive = clockwise on screen, `MatchedObject::transformAnchor` formula). ADR-0005 defines the
feature; this brief amends it with `excludeOwnFootprint` and `requiresForeground()`.

## Semantics

A `ClearanceZone` (include/mtc/clearance_zone.h) is a polygon in pattern-local pixels: origin =
the pattern's anchor point, axes = the pattern image at angle 0. `ClearanceCondition` is a
per-object `IMatchCondition` that, for every zone of `ctx.patternConfig->clearanceZones`:

1. Poses the polygon into the crop frame: `q = object.anchor + R(object.matchedAngle) * p`
   with `R` the library rotation `x' = cos*dx - sin*dy, y' = sin*dx + cos*dy` (same as
   `MatchedObject::transformAnchor`; use `geom::rotatePoint(p, origin 0, matchedAngle)` or the
   inline formula). Note `matchedAngle`, not `angle` (zones follow the pattern, not the
   reported angle with its offset).
2. Rasterizes it the way the reference did (parity for 2.7): integer points
   `cv::Point(cvRound(q.x) - bbox.x, cvRound(q.y) - bbox.y)`, `bbox = cv::boundingRect(posed
   points) & Rect(0, 0, mask.cols, mask.rows)`; empty bbox -> the zone is Ok (off-image parts
   cannot overlap anything). Convex polygon (`cv::isContourConvex` on the rounded points):
   `cv::fillConvexPoly(zoneMask, ipts, 255)`; otherwise `cv::fillPoly` (one contour).
   All zones of one object are drawn into ONE zone mask over the union bbox of all zones (the
   reference drew both boxes into one mask and counted once), so the verdict is per object.
3. Counts `zoneCount = countNonZero(zoneMask)` and
   `interCount = countNonZero(zoneMask & foreground(bbox))` where `foreground` is
   `*ctx.foreground` (CV_8UC1, 0 = free, non-zero = foreground).
   With `excludeOwnFootprint == true` (default) the object's own footprint is removed first:
   `own = *ctx.patternFootprint` (CV_8UC1, pattern size, angle 0) posed into the crop frame by
   `cv::warpAffine(own, ownPosed, M, bbox.size(), INTER_NEAREST, BORDER_CONSTANT, 0)` where `M`
   maps the pattern image to the crop: rotation about the pattern center by `matchedAngle`
   in the library sense (`cv::getRotationMatrix2D(patternCenter, -matchedAngle, 1.0)` gives
   the clockwise-on-screen matrix), then translation so the pattern center lands on
   `object.center - bbox.tl()`. Then `interCount = countNonZero(zoneMask & foreground(bbox)
   & ~ownPosed)`. If `ctx.patternFootprint` is null or empty, nothing is excluded.
4. Verdict: `interCount == 0` -> Ok. Else Ng with reason `"inside"` when
   `interCount == zoneCount` (reference state Inside: the zones lie entirely on foreground)
   else `"overlap"` (reference Collision). With `excludeOwnFootprint == false` the Ok /
   inside / overlap triple is bit-for-bit the reference `checkCollisionObject2` on the same
   mask and polygons.

Edge cases:
- `ctx.patternConfig == nullptr` or no zones -> Ok (nothing to check; log once through
  `ctx.logger` when it is set and patternConfig is null).
- `ctx.foreground == nullptr` or empty -> Ng `"no foreground"` (the facade guarantees a
  mask in edge mode; correlation groups reject the condition at configuration time).
- A zone that fails `validate()` -> Ng `"bad zone"` (do not throw).
- Foreground mask type must be CV_8UC1; otherwise Ng `"bad mask"`.

## API

```cpp
// include/mtc/match_condition.h  (addition, ADR-0005 amendment)
class MTC_API IMatchCondition {
  ...
  /// True when evaluate() needs MatchContext::foreground (edge-based mode only). The facade
  /// rejects such a condition on a correlation group at configuration time.
  virtual bool requiresForeground() const noexcept { return false; }
};

// include/mtc/builtin_conditions.h  (addition)
/// Ng when any clearance zone of the object's pattern overlaps foreground pixels.
class MTC_API ClearanceCondition final : public IMatchCondition {
public:
    /// @param excludeOwnFootprint True: pixels of the object's own posed footprint do not
    ///        count as foreground. False: reference behaviour (any foreground counts).
    explicit ClearanceCondition(bool excludeOwnFootprint = true);
    /// Returns "Clearance".
    const char* name() const noexcept override;
    /// Returns true.
    bool requiresForeground() const noexcept override;
    /// Ng ("overlap", "inside", "no foreground", "bad zone", "bad mask") as specified.
    ConditionOutcome evaluate(const MatchedObject& object, const MatchContext& ctx) const override;
    /// @return The flag given at construction.
    bool excludesOwnFootprint() const noexcept;
private:
    bool m_excludeOwnFootprint;
};

// include/mtc/clearance_zone.h  (addition; helper for legacy settings and tests)
/// Two rectangular zones of @p size placed at +/- @p distance from the anchor along the
/// direction @p angleDeg (pattern-local, clockwise positive), each rotated by @p angleDeg;
/// corners in cv::RotatedRect::points order. Names "<prefix>+" and "<prefix>-".
MTC_API std::vector<ClearanceZone> opposedBoxZones(cv::Size2f size, float distance,
                                                    float angleDeg, const std::string& prefix = "box");
```
`opposedBoxZones` reproduces the reference box geometry: reference centers were
`anchor +/- distance * (cos(a0 + m), sin(a0 + m))` with boxes at angle `a0 + m` where `m` is the
match angle; in pattern-local coordinates that is `+/- distance * (cos a0, sin a0)` and
`cv::RotatedRect(center, size, a0).points()`; posing by `m` composes to the reference.

## Implementation (src/cond/clearance_condition.cpp)

- Scratch: zero steady-state allocations, thread-safe for a shared const condition: use a
  `thread_local` scratch struct holding owned grow-only storage with `cv::Mat` headers
  (`ScratchImage` from src/edge/edge_workspace.h; if it still lives there when 2.5 starts,
  move it to `src/core/scratch_image.h` and include it from both places), plus
  `std::vector<cv::Point2f> posed; std::vector<cv::Point> ipts;` reused with clear().
- No `cv::Mat::zeros` / temporaries per call: `header.setTo(0)` on the reused storage;
  `cv::bitwise_and` into a reused header; `warpAffine` into a reused header.
- Doxygen on every symbol; reasons are the literal codes above.

## Tests (tests/unit/clearance_condition_test.cpp, synthetic only)

Helpers: a 200x200 CV_8UC1 foreground mask; a `MatchedObject` builder (center, anchor via
`transformAnchor`, matchedAngle, size); a `MatchPatternConfig` with zones; a `MatchContext`
with foreground, patternConfig and optionally patternFootprint.

1. `OkWhenZoneIsFree`: square zone to the right of the anchor, mask empty there.
2. `NgOverlapWhenZoneTouchesForeground`: a filled rectangle partially under the zone ->
   Ng "overlap".
3. `NgInsideWhenZoneLiesEntirelyOnForeground`: mask all 255 under the zone -> Ng "inside".
4. `PosesZoneWithAnchorAndMatchedAngle`: anchor off-center, matchedAngle 90: a zone at
   (+30, 0) pattern-local must land at anchor + (0, +30) in the crop (clockwise on screen),
   verified by placing foreground only there -> Ng, and at anchor + (+30, 0) -> Ok.
5. `UsesMatchedAngleNotReportedAngle`: same object with angle = matchedAngle + 45 must not
   change the verdict.
6. `ExcludesOwnFootprintByDefault`: pattern footprint = filled 40x40 square; the object's own
   square is in the mask; a zone covering part of the own square -> Ok with default, Ng with
   `ClearanceCondition(false)`.
7. `OwnFootprintPosedWithRotation`: matchedAngle 90 and an asymmetric footprint (L-shape):
   zone over the rotated L is Ok, zone over where the unrotated L would be is Ng (mask has
   foreground at both places).
8. `ClampsZoneToMask`: zone partly off-image; only the on-image part counts; a zone fully
   off-image -> Ok.
9. `NgNoForegroundWhenMaskMissing` (null and empty), `NgBadMaskOnWrongType` (CV_32F),
   `OkWhenNoZonesOrNoConfig`, `NgBadZoneOnInvalidPolygon` (2 points).
10. `NonConvexZoneUsesFillPoly`: a U-shaped zone; foreground inside the U's gap -> Ok,
    foreground on an arm -> Ng.
11. `OpposedBoxZonesMatchReferenceGeometry`: for (size 20x40, distance 60, angle 0 and 30):
    compare the 8 corner points with `cv::RotatedRect(+/-offset, size, angle).points()`.
12. `MatchesReferenceStateWithoutFootprintExclusion`: transcribe the reference
    `checkCollisionObject2` + `fillJawInto` (reference_source/matching/match_object.h lines
    198-245 and 301-312, read-only) into the test using `cv::RotatedRect(anchor +/- offset,
    size, a0 + m)` boxes; for 30 random masks (random filled rectangles and circles) x poses
    (random anchor, m in {-170, -45, 0, 33, 90, 179}) the library verdict with
    `ClearanceCondition(false)` and `opposedBoxZones(size, distance, a0)` must map exactly:
    Outside -> Ok, Inside -> "inside", Collision -> "overlap". Report any mismatch count.
13. `RequiresForegroundIsTrue` and the default `false` for `ScoreRangeCondition`.
14. `SteadyStateEvaluateDoesNotGrowAllocations` (MSVC Debug `_CrtSetAllocHook`, runs 2 and 3
