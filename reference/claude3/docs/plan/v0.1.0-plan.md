# mtc v0.1.0 - Project Plan

Status: APPROVED by the user (revision 3, 2026-10-13) together with ADR-0003/0004/0005. Priority: minimal allocation, maximum speed (see project.md "Performance goals"). Owner: the lead (Claude). Execution by Sonnet
sub-agents; reviews by an Opus reviewer. Not tracked in git.

Revision history:
- rev 2: removed picking/gripper/collision/robot concepts (ADR-0005), added conditions.
- rev 3: integrated the plan review (22 findings) and the user's clarification: built-in
  **clearance zones** (polygon overlap check, edge-based only), two-phase conditions,
  reference harness moved early, scalar twin written fresh, explicit search knobs,
  tolerances, missing tasks (CPU detection, thread-safety, error policy, export macros,
  install test, Doxygen), task splits.

## 1. Goal

Release `mtc` 0.1.0: a pure OpenCV C++ library (no Qt) that learns pattern images and finds
every instance of them in a source image (position, angle, score), with:

- **Edge-based mode** - gradient-direction edge matching ported from
  `reference_source/matching/` (pyramid, rotation search, block-max, overlap filter,
  sub-pixel, AVX2 kernels, OpenMP over angles).
- **Correlation mode** - normalized cross-correlation via `cv::matchTemplate` on the same
  pyramid + rotation-sweep skeleton.
- **Conditions** - search parameters that shape the search; per-object and set-level
  conditions that classify every match OK/NG with a reason; built-in **clearance zones**
  (user polygons checked against the foreground, edge-based only); user-pluggable
  conditions for anything else.

The library knows nothing about robots, grippers or picking.

## 3. Architecture decisions

- ADR-0001 Port the reference module; pure OpenCV; ports for cross-cutting concerns (proposed)
- ADR-0002 Keep the reference naming convention; public aggregate structs use plain camelCase
  fields, `m_` applies to class members (proposed)
- ADR-0003 Persistence with `cv::FileStorage` JSON (proposed; spike moved to M1)
- ADR-0004 Matching modes as strategies; correlation via rotation sweep (proposed; amended:
  rotate the source region as the edge mode does, score = clamp(max(0, ncc), 0, 1),
  NORMED methods only, NaN sanitized, per-layer score slack) 
- ADR-0005 No picking concepts; two-phase conditions; built-in clearance zones, edge-only
  (proposed, revision 2)

The lead asks the user to accept ADR-0003/0004/0005 before M2 starts.

## 4. Result pipeline (both modes)

```
source -> grayscale -> matching ROI crop (region)
  -> foreground extraction (ForegroundConfig): binary mask, contours, foregroundArea
  -> candidate regions: edge mode = contours whose area is within [0.7, 4.3] x pattern
     expectedArea(), padded by 70 px, processed in descending area order;
     correlation mode = the whole region as one candidate
  -> for each candidate x pattern: IMatchStrategy::search(region crop, pattern, SearchParams)
        -> Candidate{rotatedRect, center, angle, score, subpixel}
  -> global overlap pass across candidates (both modes; the reference never deduplicated
     across nested contours)
  -> MatchedObject (center, anchor, angles, score, pattern ids), crop frame
  -> per-object conditions (phase 1), may trigger stopAfterOkCount
  -> set-level conditions (phase 2)
  -> sort: OK first, then score desc or smallest |angle - sortTargetAngle|
  -> MatchResult { objects (image frame via region offset), okCount, ngCount, stats, image }
```

Early stop is "first N OK in candidate order", documented as such. In correlation mode
(single candidate) it is a post-hoc truncation.

## 6b. Notes for the regression suite (recorded during M1)

- The reference fixed-threshold branch always used THRESH_BINARY_INV regardless of
  `invertBinaryThreshold`; the port honours the flag (deliberate bug fix). Golden cases that use
  a fixed `binaryThreshold` (src5_dst5, src5_rot*, src5_*_anchor_*) therefore must be run with
  `invertBinaryThreshold = true` in the regression harness to reproduce the reference
  foreground; `cases.json` records the values the reference was given, not the effective ones.
- Fixture roles: Dst<N> is the small template, Src<N> is the scene (opposite of the file names).
- Golden `center` is the reference anchor (point_Center = transformed pickPosition);
  `rectCenter` is the mean of the corners. Golden LT/RT/RB/LB = corners()[1,2,3,0].
- Compare angles by wrapped difference; the reference may report -180 where we report 180.
- `src5` is 2-fold symmetric: rotated cases may report angle +/-180 and duplicate matches.
- M12 letters are ~4x smaller than the test scene text; no golden (edge mode is not
  scale-invariant).

- PORTING TRAP (review): the reference `ptRotatePt2f` is counter-clockwise (getRotationMatrix2D
  convention). When porting image_matcher.cpp:634/708/712 and any other reference rotation, call
  `geom::rotatePoint(p, o, -angle)`; add a unit test that rotatePoint(p,o,a) equals the reference
  formula with -a. Also add a golden-driven transformAnchor test on src5_rot90_anchor_right and
  src5_dst5_anchor_top (within 0.05 px), and pass the golden dir to tests via an MTC_GOLDEN_DIR
  definition instead of __FILE__. LOW: aligned_buffer.h doc on padding copies; pointer-compare
  assert via std::less; (backlog for the M2 first brief).

## 7. Risks and mitigations

| Risk | Mitigation |
|------|-----------|
| Edge port drifts from reference | goldens from the harness (1.10) before any port; eyeball review of annotated images |
| Scalar/SIMD divergence; thread-count dependence | fresh scalar twin, parity test, ordered OpenMP merge, 1-vs-N test |
| Clearance semantics differ from reference collision | harness records reference collision states; regression compares verdicts |
| Frame confusion crop vs image | `MatchContext` documented in crop frame with `toImage()`; tests on offset ROI |
| Correlation sweep too slow / mask unsupported | spike 3.0; top-layer sweep only; narrowed windows; benchmark gate |
| `cv::FileStorage` JSON quirks on Qt-produced files | spike 1.11 in M1; `json_schema` owns key naming; legacy samples |
| Non-ASCII in ported comments (C4819) | implementer rule, reviewer checklist, `MTC_WARNINGS_AS_ERRORS` |
| Fixtures absent in CI | synthetic tests carry CI; regression tests skip cleanly |
| Tasks too large for one agent | 2.3, 2.4, 2.6, 3.2 split; briefs capped at one component |

## 8. Tolerances

| Suite | Position | Angle | Score | Matching |
|-------|----------|-------|-------|----------|
| Regression, same compiler as golden | <= 0.25 px | <= 0.1 deg | <= 0.005 | nearest neighbour, unordered |
| Regression, other compiler | <= 1 px | <= 0.5 deg | <= 0.02 | nearest neighbour, unordered |
| Synthetic (sub-pixel off) | <= 1 px | <= half the finest angle step | n/a | by expected pose |

Matches within 0.01 of `minScore` are excluded from count comparisons. Golden files are
never edited by agents; a mismatch is reported to the lead.
