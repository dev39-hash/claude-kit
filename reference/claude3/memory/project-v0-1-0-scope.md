Decided by the user on 2026-10-13: library version **0.1.0** supports two matching modes:

- **Edge-based**: port of the reference `reference_source/matching/` algorithm (gradient
  direction edge matching, pyramid, rotation search, AVX2/OpenMP).
- **Correlation**: template matching with OpenCV `cv::matchTemplate` (NCC), rotation sweep
  on the same pyramid skeleton.
- **No picking/gripper/collision/robot concepts in the library** (user decision 2026-10-13,
  ADR-0005). Instead: search conditions (score, angle tolerance, overlap, ROI, max count,
  early stop) plus a pluggable `IMatchCondition` stage that classifies each match OK/NG with
  a reason (two phases: per-object and set-level); built-ins shipped. The overlap check
  stays in the library as **clearance zones** (user polygons in pattern coordinates checked
  against the foreground mask by `ClearanceCondition`), **edge-based mode only**, clarified
  by the user on 2026-10-13; legacy gripper boxes convert to two zones. `IRobotPickingChecker`
  is a user-side example only. `m_pickPosition` -> `m_anchorPoint`, `m_angle` -> `m_angleOffset`.

The plan lives at `.claude/docs/plan/v0.1.0-plan.md` (milestones M0 bootstrap, M1 core
types, M2 edge port, M3 correlation, M4 Qt-free persistence via `cv::FileStorage`, M5
release). Design decisions: ADR-0003 (FileStorage JSON persistence) and ADR-0004
(`IMatchStrategy` + correlation design, amended) and ADR-0005 (conditions + clearance zones),
all `proposed` and awaiting the user's acceptance; plan rev 3 integrated a 22-finding review. Golden regression data is to be generated by a local reference harness
built from the reference sources (which compile without Qt except the manager).

**Approval and priority:** the user approved plan rev 3 and ADR-0003/0004/0005 on 2026-10-13
and set the priority for 0.1.0: minimal memory allocation and the highest execution speed
(allocation-free hot paths, reusable workspaces, SIMD everywhere; see project.md
"Performance goals").
